# G1 / Inside the Signal — GitHub Pages visual lab

The site lives entirely in this \`docs/\` directory and is independent of the embedded project. It adds:

- A responsive, motion-rich engineering design showcase and a 3D assembly viewer (drag, zoom, rotation, camera presets, wireframe, housing, exploded assembly).
- A dual-path Bluetooth/telecoil functional signal-map and **real** GitHub-sourced C code browser.
- A filterable schematic gallery. The Pages publish workflow uses KiCad to export the **original tracked hierarchical schematic** to zoomable SVGs. It links back to each \`.kicad_sch\` source.
- Clear distinctions between host-only tests, unfinished physical validation, and publication rights.

## Publish it

1. Review the rights to show any team/assessment/PCB/CAD content on a public website. GitHub Pages is publicly accessible. This repository is currently public; publishing a site does not constitute a licence or a device safety claim.
2. In **G1 repository → Settings → Pages**, set **Build and deployment → Source → GitHub Actions**.
3. In **Actions**, select **Publish G1 Interactive Lab (GitHub Pages)**, then **Run workflow** on \`main\`. The workflow validates the site, installs KiCad for rendering, exports SVG schematic sheets, and deploys **only \`docs/\`**.
4. After a successful Pages deployment, open the URL listed in the deployment job, expected to be \`https://rv-crtl.github.io/Digital-Hearing-Aid-G1/\`. Do not claim this address is live until the workflow actually publishes successfully.

The dedicated \`G1 Visual Lab — website integrity\` workflow runs for site-related pull requests and checks routes, repository references, JS/Python syntax and the publication boundary. It **does not deploy a preview to a public URL**.

## Include the actual supplied assembly

The Three.js viewer looks for \`docs/assets/g1-assembly.glb\`. If the file is absent, it shows an explicitly labelled **conceptual** hardware fallback rather than pretending to show the source CAD.

To install the real CAD-derived assembly:

1. Convert your authorised \`.3mf\` with \`python Tools/convert_3mf_to_glb.py "your-model.3mf" "docs/assets/g1-assembly.glb"\`, after installing \`trimesh numpy lxml\`. Alternatively use the already converted GLB supplied separately in the conversation.
2. Upload that 3D file to **exactly** \`docs/assets/g1-assembly.glb\` in this G1 repository using GitHub's **Add file → Upload files**; create the \`docs/assets\` folder if necessary. The supplied mesh is several megabytes and should be treated as a genuine public design disclosure; upload only if team/rightsholder clearance is established.
3. Run the Pages publishing workflow again. Once installed, the viewer reports **“CAD-derived model loaded”** and renders the detailed assembly instead of the conceptual fallback.

The companion conversion utility groups the original 3MF into Shell, PCB, Copper, Electronics, Components and Contacts, retaining triangular geometry and 3MF group colours where supplied. It reduces draw calls by merging objects into coherent rendering layers; it does **not** claim CAD-to-GLB produces a parametrically editable STEP model.

## Schematic viewer provenance

The gallery reads \`docs/plots/manifest.json\` generated by \`docs/render_kicad.py\` and displays the original KiCad SVG plots whenever the Pages workflow exports them successfully. If the export fails, it clearly labels the fallback card artwork as an *abstract design map*, and direct links to actual \`Hardware/Original_KiCad/*.kicad_sch\` still work.

KiCad **ERC and DRC are not executed** here. Some source references to third-party symbol and footprint libraries remain unresolved. The site is an educational engineering showcase, not proof of an approved, fabricated device.

## Local development and verification

From the repository root, use:

\`\`\`bash
python docs/validate_site.py
node --input-type=module --check < docs/app.js
node --input-type=module --check < docs/viewer.js
python -m http.server 8000 --directory docs
\`\`\`

Visit \`http://localhost:8000\`. Loading native WebGL and real code previews requires internet access for the pinned Three.js module CDN and public GitHub source. A plain \`file://\` open is not sufficient for browser module imports and fetch operations. The website uses no analytics, no server/database, and no device-control back end.

Site code is solely a user interface; never use the interactive signal-map as a measured real-time physical recording.
