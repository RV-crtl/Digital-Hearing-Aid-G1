# G1 / Inside the Signal — GitHub Pages visual lab

The site lives entirely in this `docs/` directory. It documents the current software separately from the standalone custom-PCB target and its remaining firmware verification gates. It adds:

- A responsive, motion-rich engineering design showcase and a 3D assembly viewer (drag, zoom, rotation, camera presets, wireframe, housing, exploded assembly).
- A dual-path Bluetooth/telecoil functional signal-map and **real** GitHub-sourced C code browser.
- A filterable schematic gallery. The Pages publish workflow uses KiCad 10 (matching the source format) to export the **original tracked hierarchical schematic** to zoomable SVGs. It links back to each `.kicad_sch` source.
- Clear distinctions between host-only tests, unfinished physical validation, and publication rights.

## Publish it

1. Review the rights to show any team/assessment/PCB/CAD content on a public website. GitHub Pages is publicly accessible. This repository is currently public; publishing a site does not constitute a licence or a device safety claim.
2. In **G1 repository → Settings → Pages**, set **Build and deployment → Source → GitHub Actions**.
3. In **Actions**, select **Publish G1 Interactive Lab (GitHub Pages)**, then **Run workflow** on `main`. The workflow validates the site, installs KiCad for rendering, exports SVG schematic sheets, and deploys **only `docs/`**.
4. After a successful Pages deployment, open the URL listed in the deployment job, expected to be `https://rv-crtl.github.io/Digital-Hearing-Aid-G1/`. Do not claim this address is live until the workflow actually publishes successfully.

The dedicated `G1 Visual Lab — website integrity` workflow runs for site-related pull requests and checks routes, repository references, JS/Python syntax and the publication boundary. It **does not deploy a preview to a public URL**.

## The authentic hosted 3D assembly

The repository contains the actual original **3MF** CAD archive at `docs/assets/g1-assembly.3mf`. Previous revisions accidentally named the same ZIP-format bytes `.glb`; this is now fixed. The Pages build converts that original file into a genuine, optimized GLB using the checked-in converter; the viewer loads the generated GLB first and falls back to the unmodified original 3MF for source previews. It does **not** substitute fictional electronics. Large assemblies can still require desktop-class memory and GPU resources.

The **Open your 3D CAD** control also allows local `.3mf` or genuine `.glb` files without uploading them. Optional offline conversion: `python Tools/convert_3mf_to_glb.py docs/assets/g1-assembly.3mf /path/to/output.glb` (requires `trimesh`, `numpy`, `lxml`). Convert and verify a true `glTF` header before changing the public viewer path.

The source model already exists in this public repository, but public availability does **not** establish ownership, redistribution permissions, medical compliance or acoustic safety. Rights-holder clearance remains necessary before claiming an approved release. See [publication gate](../Documentation/PUBLICATION_GATE.md).

## Schematic viewer provenance

The gallery reads `docs/plots/manifest.json` generated by `docs/render_kicad.py` and displays the original KiCad SVG plots whenever the Pages workflow exports them successfully. If the export fails, it clearly labels the fallback card artwork as an *abstract design map*, and direct links to actual `Hardware/Original_KiCad/*.kicad_sch` still work.

KiCad **10.0.x** is required by the original schematic version (20260306). The workflow installs the KiCad 10 PPA and checks that actual SVG sheets render. KiCad **ERC and DRC are not executed** here. Some source references to third-party symbol and footprint libraries remain unresolved. The site is an educational engineering showcase, not proof of an approved, fabricated device.

## Local development and verification

From the repository root, use:

```bash
python docs/validate_site.py
node --input-type=module --check < docs/app.js
node --input-type=module --check < docs/viewer.js
python -m http.server 8000 --directory docs
```

Visit `http://localhost:8000`. Loading native WebGL and real code previews requires internet access for the pinned Three.js module CDN and public GitHub source. A plain `file://` open is not sufficient for browser module imports and fetch operations. The website uses no analytics, no server/database, and no device-control back end.

Site code is solely a user interface; never use the interactive signal-map as a measured real-time physical recording.

## G11: complete signal and task map

The [system atlas](index.html#architecture) is a single-page, keyboard-accessible diagram of Bluetooth, telecoil, and proposed PDM microphone routes, including serial words, circular RX DMA, completed-half snapshots, task notifications, AudioTask ownership, PCM FIFO, SAI2B TX DMA and output electronics. It explains 2 × 26650 LiFePO4 3.25 V nominal cells **in series**, uses no NUCLEO as part of the final operating system, and shows the RTOS hierarchy with clickable production C sources. The contextual preference demo is a **browser simulator**, with portable algorithm source in `Core/Src/adaptive_preferences.c`, not a field-ready learned device.

For the rubric and bench acceptance, see [standalone custom-PCB release plan](../Documentation/G11_STANDALONE_CUSTOM_PCB_RELEASE_PLAN.md). The original `docs/assets/g1-assembly.3mf` is retained and loaded when a generated GLB is unavailable; the manually triggered Pages workflow generates the real GLB before deployment. Source-licensing review and physical-board acceptance remain separate requirements.
